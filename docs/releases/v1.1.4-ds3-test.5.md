# LibrePadPS5 1.1.4-ds3-test.5

Targeted USB streaming build for [issue #4](https://github.com/arwebSE/LibrePadPS5/issues/4).
Test 4 completes F2/F5 and LED requests, but its reader receives an initial
neutral report followed by prolonged idle periods. Reopening repeats that
pattern. Successful setup and recovery do not establish sustained input.
The unbound virtual-pad message does not explain the absence of USB reports.

## Changes

- After F2/F5, send the USB reporting-enable feature command:
  `SET_REPORT F4`, payload `42 0c 00 00`, on the independent control handle.
  Both [USB Host Shield](https://github.com/felis/USB_Host_Shield_2.0/blob/master/PS3USB.cpp)
  (`enable_sixaxis`) and
  [Open PS2 Loader](https://github.com/ps2homebrew/Open-PS2-Loader/blob/master/modules/ds34usb/iop/ds34usb.c)
  (`DS3USB_init`) use this command for USB input. It differs from the old
  Bluetooth `42 03` command. Our F2/F5 path had omitted this USB enable request.
- Log the enable request's result, error and actual length. Unsupported or
  short enable writes retain the existing F2/F5 input path for compatibility.
- Add a rate-limited physical-input summary: nonempty reports received,
  completed input timeouts, successful read starts, pending-read state and age,
  and age of the last report. Counts reset when the transport is reopened.
  These counts describe the physical USB transport, not virtual-pad frames.
- Preserve independent handles, deferred output and bounded recovery from test 4.

The missing enable request is a concrete difference from working USB drivers.
It is not yet confirmed as the cause of the reporter's stalled stream.
The normal release remains v1.1.3.

## Test

1. Stop test 4 and load this release's ELF. For Payload Manager, replace the
   ELF and JSON together. Confirm `1.1.4-ds3-test.5` in the dashboard.
2. Connect one DS3 and press physical PS. Move both sticks and press buttons
   for 30 seconds. Reconnect/assign its virtual pad if necessary.
3. Attach a fresh diagnostic report. The USB enable result and physical-input
   counters distinguish an active stream, repeated timeouts and a stuck read.

## Validation

- Combined PS5 SDK v0.43 payload built successfully.
- AddressSanitizer/UndefinedBehaviorSanitizer USB transport tests passed.
  The mock checks the exact USB F4 request, payload and interface, preserves
  F2/F5 reports after failed/short enable writes, delivers 100 subsequent
  changing reports, and verifies that 30 successive timeouts re-arm correctly
  before later button input. Existing ownership, output, recovery worker and
  XInput tests passed. Mocked transfers do not verify physical DS3 behavior.
- Repository punctuation, include/documentation and diff checks passed.
- Hardware verification of continued input is pending.
