# LibrePadPS5 1.1.4-ds3-test.2

Second targeted DS3 USB test for [issue #4](https://github.com/arwebSE/LibrePadPS5/issues/4#issuecomment-6146606498).
The tester's first-build log confirms several successful F2/F5 exchanges and
49-byte input reports, including decoded PS-button presses. Other attempts
fail during initialization or stop receiving input. Console navigation and
continuous input are still unconfirmed.

## Changes from test 1

Send a one-time DS3 output configuration after the first valid full USB input
report. This follows the deferred initialization in
[Linux's Sony HID driver](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-sony.c).
It uses HID SET_REPORT on the control endpoint, with the report ID carried in
the request rather than the data. It selects the virtual slot's player LED and
leaves both motors off.

The next USB read stays armed during the write. Output failure is logged and
does not discard incoming input or trigger repeated writes. F2/F5 diagnostics
and the combined USB, Xbox Wireless and opt-in Bluetooth support remain.
This is a test of the missing output step, not a confirmed explanation for all
initialization failures or disconnections in the report.

## Test steps

1. Stop the running payload with the dashboard's **Stop payload** button and
   load this release's `LibrePadPS5.elf`. For Payload Manager, replace the ELF
   and JSON together. Confirm version `1.1.4-ds3-test.2` in the dashboard or
   startup notification.
2. Connect one DS3 with a USB data cable and press its physical **PS** button.
3. Select its pad in the dashboard's **Controller** tab. If it is released,
   select **Reconnect**. The previous report had `paused=1`; that state persists
   across payload restarts and prevents virtual input until Reconnect.
4. Assign a separate signed-in PS5 user, press physical **PS** again, then move
   both sticks and press Cross, Circle and the D-pad for around 15 seconds.
5. Download a fresh diagnostic report under **Advanced > Logs & support** and
   attach it to issue #4. Mention whether a player LED becomes steady, whether
   dashboard sticks/buttons move, whether console navigation works and whether
   the DS3 is an original Sony unit or a compatible model, if known.

The new diagnostic line is `DS3 deferred USB output completed/failed`, with the
actual transfer result and length. No settings reset or Xbox firmware is needed
for DS3 testing. The normal release remains v1.1.3.

## Validation

- Combined payload compiled and linked with PS5 SDK v0.43 and LLVM.
- USB transport suite passed on Windows with AddressSanitizer and
  UndefinedBehaviorSanitizer, mocked transfers and temporary POSIX header shims.
- New cases cover deferred output, all four player LEDs, disabled motors,
  input queued during the write, failed/short writes, partial/wrong-ID reports
  and input-start failure. Existing F2/F5 and XInput cases also passed.
- Repository punctuation, include/link and diff checks passed.
- Physical DS3 validation of this second build is pending.
