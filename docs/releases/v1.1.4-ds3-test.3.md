# LibrePadPS5 1.1.4-ds3-test.3

**Retired diagnostic build.** Use the [latest stable ELF](https://github.com/arwebSE/LibrePadPS5/releases/latest/download/LibrePadPS5.elf).
Future test builds are ZIP attachments in [issue #4](https://github.com/arwebSE/LibrePadPS5/issues/4), not releases.
The notes below preserve the investigation history; this retirement does not confirm a DS3 fix.

Targeted USB recovery build for [issue #4](https://github.com/arwebSE/LibrePadPS5/issues/4).
The test 2 report confirms successful USB wake-up and output configuration,
plus PS, L1 and L2 input. It also shows the reader exhausting its 50-error
counter in about two milliseconds, which removes the virtual controller and
loses its assignment before a temporary transport failure can recover.
The cause of the underlying USB failures is still unconfirmed.

## Changes

- On a DS3 read failure, neutralize held input immediately while retaining the
  same controller owner and virtual slot.
- Reopen its USB transport after delays of 100, 200 and 400 ms, with at most
  three attempts per recovery episode. Replace the old USB_FS state and repeat
  endpoint discovery, USB wake-up and deferred output configuration.
- Check the reopened device's VID/PID before claiming an interface or sending
  wake-up commands. A different device on that path is rejected.
- Retain the virtual controller and assigned user on successful recovery.
  Exhausted attempts or shutdown return to normal device removal.
- Let an in-progress recovery complete if the device path briefly disappears
  during the hotplug scan. Explicit shutdown still cancels recovery.
- Log recovery attempts, identity failures, successful restoration and the
  DS3 interface-claim result.

This replaces the DS3 reader's rapid error-counter teardown. It does not prove
that the physical USB connection or every controller revision is now stable.
The normal release remains v1.1.3.

## Test

1. Stop the old payload and load this release's `LibrePadPS5.elf`. For Payload
   Manager, replace the ELF and JSON together. Confirm `1.1.4-ds3-test.3` in
   the startup notification or dashboard.
2. Connect one DS3, select its pad in the dashboard and use **Reconnect** if
   released. Assign its separate signed-in PS5 user and press physical **PS**.
3. Keep it connected while moving the sticks and pressing buttons for around
   30 seconds. Check whether it keeps controlling the same PS5 user if a USB
   interruption occurs.
4. Download a new report from **Advanced > Logs & support** and attach it to
   issue #4. Capture it while the virtual pad is active.

The recovery log identifies whether reopening restored input or failed. Existing
settings and combined USB, Xbox Wireless and opt-in Bluetooth support remain.

## Validation

- Combined PS5 SDK v0.43 payload built and linked with LLVM.
- Sanitized host USB transport suite passed, including execution of the actual
  reader worker. Transfers and file operations are mocked; the Windows host
  uses temporary POSIX header shims.
- New tests cover successful recovery, a delayed reopen, retry exhaustion,
  failed descriptor/handshake, shutdown cancellation, unchanged owner/slot,
  neutral input on failure, resumed input, and rejection of a DualSense replacing
  the DS3 on the same USB path.
- Existing F2/F5, output configuration and XInput transport tests passed.
- Repository punctuation, include/link and diff checks passed.
- Physical console validation of recovery is pending.
