LibrePadPS5 v0.5.1-preview addresses the two user reports in [issue #1](https://github.com/arwebSE/LibrePadPS5/issues/1): silent startup on PS5 13.60 and an 8BitDo USB Wireless Adapter 2 that does not provide input.

- Added versioned **starting** and **ready** notifications. Duplicate instances, state-directory/lock errors, invalid controller profiles, rejected firmware, virtual-pad initialization failure and dashboard startup failure now produce an on-screen explanation. Failed notification requests are logged too.
- Fixed the 8BitDo driver's rejection of XInput vendor interfaces. Prefer the matching XInput interface over unrelated HID functions, keep input/output endpoints on the same interface, and address initialization transfers to that interface.
- Added known 8BitDo XInput IDs `2dc8:3106` and `2dc8:3109`. Xbox-identity XInput devices (`045e:028e`) continue to use the Xbox driver. Unsupported modes now leave a useful USB diagnostic.
- The dashboard/API displays the payload version so testers can confirm the build actually running.
- Includes the current mainline Xbox Wireless module and up to three independent virtual slots, with per-pad release/reconnect, profile assignment and native-profile reservations. One Xbox Wireless controller is supported; its receiver firmware must be staged separately.

**For the 13.60 reporter:** stop any running instance, then load this ELF once. Look for `LibrePadPS5 0.5.1-preview: starting` followed by either `ready` or the failure explanation. Open `http://<PS5_IP>:8096/`. If startup still fails, retrieve `/data/pdp-pad/pdp-pad.log` through FTP and include the new version/firmware lines, the error, and your ELF loader name/version. If neither a notification nor a new log entry appears, include the loader output: the application may not have reached its entry point. The firmware gate accepts 13.60; this release does not claim verified hardware compatibility on 13.60.

**For the Adapter 2 reporter:** pair the controller to the adapter, explicitly select **XInput mode**, then unplug/replug the adapter. For DualShock 4, hold Share + D-pad Up for three seconds until the adapter LED blinks twice. Use the corresponding combination in [8BitDo's controller-specific manual](https://support.8bitdo.com/Manual/USB-Adapter-2/ps4-windows.html) for another controller. Leave the payload's Bluetooth disabled; the adapter handles pairing. Click Reconnect and assign a separate PS5 profile. If input still fails, include the dashboard log, adapter VID/PID, adapter mode and paired controller model.

Validation: 14 host regression suites passed with AddressSanitizer/UndefinedBehaviorSanitizer, including startup at the 13.60 firmware bounds, failure/duplicate-instance notifications, USB interface selection, malformed descriptors, HTTP, lifecycle and simulated Bluetooth (including 200,000 fuzz inputs). All five Xbox Wireless host suites passed with sanitizers. Dashboard keyboard/tab checks and the PS5 SDK v0.43 release build passed.

Hardware status: the earlier PDP `0e6f:0184` and Xbox One model 1697 / receiver `045e:02e6` combination was verified on PS5 12.60. This release has not been loaded onto a live PS5. The reported 13.60 setup and 8BitDo Adapter 2 still need user confirmation; issue #1 remains open.

Download `LibrePadPS5.elf`; the matching Payload Manager JSON and SHA-256 file are attached. Keep the existing `/data/pdp-pad/` settings and stop the old instance before upgrading. Use separate console profiles and reserve native DualSense profiles in Advanced. Xbox receiver firmware is supplied separately. Bluetooth remains opt-in.
