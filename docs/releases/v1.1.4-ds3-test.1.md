# LibrePadPS5 1.1.4-ds3-test.1

**Retired diagnostic build.** Use the [latest stable ELF](https://github.com/arwebSE/LibrePadPS5/releases/latest/download/LibrePadPS5.elf).
Future test builds are ZIP attachments in [issue #4](https://github.com/arwebSE/LibrePadPS5/issues/4), not releases.
The notes below preserve the investigation history; this retirement does not confirm a DS3 fix.

Targeted USB DualShock 3 test build for [issue #4](https://github.com/arwebSE/LibrePadPS5/issues/4).
The normal download remains v1.1.3. Physical DS3 input on PS5 firmware 11.40
still needs confirmation from the reporter.

## Changes

- Replace the Bluetooth-style F4 wake-up request with USB feature reads F2
  (17 bytes) and F5 (8 bytes), following the USB operational sequence in
  [Linux's Sony HID driver](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-sony.c).
- Arm USB input before wake-up and preserve a packet arriving during initialization.
- Check both request results and returned lengths. Failed, empty or short
  responses no longer claim successful initialization.
- Log the first DS3 USB input packet and throttle repeated USB completion
  failures so useful startup information remains in the diagnostic report.
- Keep the combined USB, Xbox Wireless and opt-in Bluetooth payload.

## Try this build

1. Use the dashboard's **Stop payload** button to stop the running build.
2. Load this release's `LibrePadPS5.elf` with your usual loader. Existing
   settings and storage paths are retained.
3. Unplug and reconnect one DS3 with a USB data cable, then press the physical
   **PS button on the DS3**. Move its sticks and press a few buttons.
4. Check the dashboard input display and console navigation with the controller's
   separate PS5 user. Test the second DS3 separately if the first still fails.
5. Use **Advanced > Logs & support > Download diagnostic report (.txt)** and
   attach the new report to issue #4, including whether input worked and what
   the controller LEDs did.

The startup notification and diagnostic report should identify
`1.1.4-ds3-test.1`. The new log records each F2/F5 result and whether a first
USB input packet arrived. A successful wake-up alone does not confirm working
controller input.

For Payload Manager, use the ELF and JSON from this test release together.
To return to v1.1.3, stop this payload and load the normal release again.

## Validation

- PS5 SDK v0.43 combined payload compiled and linked successfully with LLVM.
- USB transport, protocol and PDP report suites passed with AddressSanitizer
  and UndefinedBehaviorSanitizer on a Windows host. The transport suite uses
  mocked USB transfers and temporary POSIX header shims; no console or physical
  DS3 was used for these tests.
- Transport tests cover ordered F2/F5 requests on interfaces 0 and 2, failed
  and invalid-length transfers, input-start failure, queued DS3 input and its
  button/stick decoding, existing XInput behavior and throttled completion errors.
- Repository include/link, punctuation and diff checks passed.
